# Super-Agent 战略规划与架构路线（ROADMAP v2）

> 一句话纲领：**LLM 是发动机已经很强，我们做的是那个不会越用越坏的"载体"。**
> 载体的第一性原理 = **一切资源预算受限，按重要度分级、按活跃度调度、按生命周期淘汰。**

---

## 0. 核心洞察：为什么所有 agent "越用越不好用"

| 症状 | 病根 | 类比 |
|---|---|---|
| 上下文太多、越来越贵、越用越笨 | 上下文只增不减，无预算无压缩无淘汰 | 内存泄漏 |
| 记忆太短/太多/太杂乱 | 记忆无分层无去重无GC | 垃圾堆 |
| skills/MCP/工具混乱臃肿 | 全量载入，无分级无惰性 | CPU 满载 |
| 任务越拖越慢、越卡 | 无分配调度，无预算无超时 | 进程爆炸 |

**结论：agent 缺的不是能力，是像操作系统的"资源调度器"。**

## 3. 长期任务 + 死循环自查（你要的特重要模块）

**你的修正：三次失败不是"停止"，而是"进入自查"。** 这是核心升级。

### 3.1 自查模块（Self-Check）——失败后的第一动作
连不上/执行失败 → **不盲目重试、不直接放弃**，而是进入自查：
1. **诊断**：这次为什么失败？（分类：权限/环境/缺信息/不可行/参数）
2. **根因自查**：DNS？防火墙？服务没起？目标地址变了？（用诊断工具验证，不猜）
3. **自愈尝试**：可自动修复则修（重装服务、换地址、清缓存、重连）
4. **确认**：修复后重验，真成功才进入下一步

### 3.2 连贯任务队列（依赖有序执行）
当任务 1→2→3 有前后依赖：
- **严格串行**：任务1 未自查通过 + 未真正成功，**绝不进入任务2**
- 每完成一个，**验证门禁通过 + 自查确认**，才推进下一个
- 链条中任一环失败 → 该环及后续全部进入"未完成清单"

### 3.3 上报 / 未完成清单 / 进度提示（你要的可见性）
| 机制 | 作用 |
|---|---|
| **进度条** | 长任务实时显示当前/总步数、每步状态 |
| **失败上报** | 任一环失败 → 明确提示"哪步失败、为什么、未完成清单已记录" |
| **未完成清单** | 所有失败/暂停任务进清单，可 /resume 续跑，不丢失 |
| **通知** | 跨表面推送（TUI/Telegram）：任务开始/完成/失败 |

## 4. 安全哲学（你的关键修正：不做市面那种死板门禁）

**原则：安全用于防误伤，不用于妨碍自己人。**

- ✅ **不设死板门禁**：重启 agent、执行命令等自己的操作不被无理拦截
- ✅ **密码自管**：密码本加密存储，但**可用特殊方式解密成明文查看**（不是银行/支付密码，无需那级防护）
- ✅ **服务器密码等收录**：自己的凭据密码本统一管理，凭据重要性分级
- ⚠️ 仅保留**防误伤**保护：`rm -rf /` 这类高危操作轻提醒，不拦截自己人

## 5. 全平台客户端 + 一键安装

**目标：`curl | bash` 秒装，全平台（除 iOS），Rust 客户端。**

```
Linux/macOS: curl -fsSL https://<repo>/install.sh | bash
Windows:     irm https://<repo>/install.ps1 | iex
```
安装向导：检测 OS/arch → 装 Rust 客户端 + Python 身体 → 装 superbrain 内核 → 生成 .env → 交互填 API/bot → `sa` 命令就绪。
装不了的依赖 → 预编译 wheel / 内嵌 vendor 打包进发行版。
GitHub Actions 自动出多平台包（Linux/macOS/Windows；iOS 发布难暂不做）。

## 7. 图片压缩（你的问题：已知最好的算法）

**诚实结论（已核查）**：Squoosh 本身**不是一个算法**，是 Google 把业界主流编码器打包的 Web 工具。真正的"最好"取决于场景：
- **照片/有损高压缩**：**AVIF**（libaom）—— 现代照片最佳质量体积比
- **无损/高保真/宽色域**：**JPEG XL** —— 最好但浏览器/工具支持有限
- **截图/图形**：WebP / OxiPNG
- **学界 SOTA（ML 学习压缩）**：HiFiC 等基于神经网络的编码器在极低码率下质量最高，但慢且重

**落地策略**：Rust 客户端内嵌 **AVIF + JPEG XL + WebP** 编码器（借 Squoosh 所用的 libaom/libjxl 思路），后续可接 ML 编码器优化。

## 8. 上下文治理（你的核心认可 + 更细机制）

**你的核心要求：不是全塞进上下文，而是"挑出有用的部分输入"。**

三层机制 + **精挑输入**：
1. **上下文预算**：每次会话设 token 预算，超了自动压缩/归档
2. **记忆分层**：热(上下文)/温(检索)/冷(归档) —— 大脑已做 L0-L4
3. **工具分级**：不全部载入，按任务相关性惰性注入
4. **项目感知精挑（新增，你要下功夫的点）**：
   - **输入前明确**：现在在做什么项目？当前目标是什么？
   - **只挑相关**：只把当前项目相关的记忆/工具/历史喂给模型，**无用废话不输入**
   - **上下文切片**：长历史按项目/时间切片，只带当前切片

## 9. 分阶段路线

- **Phase 1 稳定性**：自查模块 + 连贯任务队列 + 熔断器/重试/超时 + 未完成清单 + 进度条 + 命令沙箱回收
- **Phase 2 上下文治理**：token 预算压缩 + 工具惰性加载 + 项目感知精挑输入 + 记忆分层打通
- **Phase 3 发布**：Rust 客户端 + install.sh/ps1 + 打包 + GitHub Actions 多平台
- **Phase 4 资产与存储**：存储空间规划 + 资产文件夹 + AVIF/JPEG XL 图片压缩
- **Phase 5 密码本与安全自管**：加密密码本 + 可解密查看 + 防误伤保护

> 全部机制都要求**真实验证**（不堆营销词）：自查用坏服务器测、进度条用长任务测、图片压缩用真实截图测体积、安装脚本在干净环境测。
