# Super-Agent 战略规划与架构路线（ROADMAP）

> 一句话纲领：**LLM 是发动机已经很强，我们做的是那个不会越用越坏的"载体"。**
> 载体的第一性原理 = **一切资源预算受限，按重要度分级、按活跃度调度、按生命周期淘汰**。

---

## 0. 核心洞察：为什么所有 agent "越用越不好用"

用户观察完全正确，且直指根因。症状与病根：

| 症状 | 病根 | 类比 |
|---|---|---|
| 上下文太多、越来越贵、越用越笨 | 上下文**只增不减**，无预算无压缩无淘汰 | 内存泄漏 |
| 记忆太短 / 太多 / 太杂乱 | 记忆**无分层无去重无GC**，检索命中率随数据量下降 | 垃圾堆 |
| skills / 工具混乱、臃肿、又多 | 工具**全量载入**，无分级无惰性加载 | CPU 满载 |
| 任务越拖越慢、越卡 | **无分配调度**，历史残留任务堆积 | 进程数爆炸 |

**结论：agent 不是缺能力，是缺一个像操作系统的"资源调度器"。**
把上下文 / 记忆 / 工具 / 任务 四种资源，都纳入「预算 → 分级 → 调度 → 回收」的生命周期管理。

## 1. 对标产品破译（Claude Code / Codex / Hermes）

| 维度 | Claude Code | Codex(OpenAI) | Hermes | 我们 |
|---|---|---|---|---|
| 上下文管理 | 有 compression | 保守窗口 | strategic-compact 压缩 | **预算+压缩+归档三件套** |
| 长期记忆 | 弱(会话内为主) | 弱 | memory 分层+skills 自学习 | **独立大脑内核=记忆专用** |
| 工具治理 | 单一工具生态 | 精简 | skills 惰性加载 | **工具分级+按需注入** |
| 多表面 | 终端/IDE | 终端 | 桌面/Web/TG/CLI/TUI/IDE | **Body 层多表面** |
| 分化点 | / | / | / | **"身体+大脑"分离，分开更新；全资源分级调度** |

**结论：Hermes 是最接近"载体"的产品（多表面+记忆+skills+后台），但它是"通用全功能框架"，堆得越多越重；我们的差异化是"大脑=内核、身体=执行"的极简分离 + 真正的资源调度器。** Claude Code/Codex 在记忆与载体哲学上不如我们方案。

## 3. 死循环防护（你第一个点名的痛）

场景：让 agent 连一台出问题的服务器 → 一直重试一直连不上 → 卡死。

**这不是"再加个超时"能解决的，要一套"任务保命网"：**

| 机制 | 作用 | 现状 |
|---|---|---|
| **重试预算** | 每次连接/操作有硬上限（默认 3 次），超了放弃 | AgentLoop 有 max_steps，需补**每次调用级** retry |
| **指数退避** | 重试间隔 1s→2s→4s，不狂轰滥炸 | 需补 |
| **熔断器 CircuitBreaker** | 同一目标连续失败 N 次 → 熔断 30s，不再尝试 | 需补 |
| **全局超时** | 每个任务/每次 LLM 调用有墙钟时限 | 需补 |
| **幂等操作** | 连接/写文件/调 API 支持"重试安全" | 工具层需标注 |
| **死信 + 失败分类** | 放弃后按类别处置（改目标/换路/求助） | ✔ 已有 FailureClassifier |
| **用户随时打断** | Ctrl-C / Telegram /stop / 任务 cancel | ✔ 已有 cancel |

**核心新模块：`safety/circuit.py`（熔断器）+ 把重试预算接进 AgentLoop 的每次工具调用。**

## 4. 安全规则（你点名的第二个痛）

**原则：不安全操作不是"禁止"，而是"门禁"。** 复用已有 BodyPolicy + VerificationGate：

- **权限分级**：read-only / workspace / unrestricted（已有）
- **危险操作门禁**：`rm -rf` / 系统目录 / 生产 DB / 外发请求 → 需批准或自动拦截
- **路径沙箱**：工具默认锁在 workspace，越界需明确授权（已有 _path 校验）
- **危险清单**：内置高危模式库（`shutil.rmtree('/',...)`、`DROP TABLE`、`git push --force`…）
- **审计日志**：每次外部副作用（网络/写盘/执行）留痕，可回看

## 5. 全平台客户端 + 一键安装（你点名的第三个大方向）

**目标：像 Hermes 一样 `curl | bash` 秒装，全平台（除 iOS），自动装依赖，装不了的打包进 agent。**

**语言策略（你的问题：Python 有授权/性能短板）：**
- **主语言 Python**：身体/编排/工具/TUI 用 Python（生态最全，Hermes/Claude Code 同为）
- **高性能内核 Rust**：superbrain-2.0 已是 Rust（记忆/检索/并发），性能热点在 Rust，Python 负责编排 → 天然混合
- **系统级操作原生脚本**：Linux 用 sh，Windows 用 .ps1/bat，macOS 用 zsh —— 安装器和系统调用用各平台原生脚本
- **"免授权"执行**：优先走用户态（venv 内、普通权限）；需提权的操作显式声明并提示，不静默 sudo

**一键安装（三平台）：**
```
Linux/macOS:  curl -fsSL https://<repo>/install.sh | bash
Windows:      irm https://<repo>/install.ps1 | iex
```
安装向导流程（参考 Hermes install.sh）：
1. 检测 OS/arch → 2. 装 uv + Python venv → 3. 装 superbrain 内核(editable) + rich
4. 生成 .env → 5. 交互填 API/bot → 6. 启动向导 → 7. `sa` 命令就绪
装不了的依赖（缺编译/平台）→ 预编译 wheel / 内嵌 vendor 打包进发行版。

**发行形态：**
- `uv tool`/`pipx` 安装包（Python 生态标准）
- 可选 PyInstaller/Nuitka 打单文件可执行（免 Python 环境）
- GitHub Actions 自动出多平台安装包（Linux/macOS/Windows；iOS 发布难，暂不做）

## 6. 无授权执行 + 资源回收 + 脚本复用（你的担心）

| 问题 | 方案 |
|---|---|
| **执行授权烦** | 统一走"命令沙箱执行器"：普通命令直接跑；危险命令走门禁；不逐个交互。`shell` 工具封装，长脚本一次交付 |
| **留垃圾** | **事务化执行**：每次任务工作目录隔离（`/tmp/sa-<taskid>/`），任务结束**自动回收**临时文件；git worktree 用 `-w` 避免冲突；会话退出清理 |
| **脚本复用** | **脚本库**：常用操作沉淀为可复用脚本（带参数+幂等+返回码检查）；AgentLoop 优先查库再新写；模板化避免重复造 |

**核心新模块：`exec/sandbox.py`（命令沙箱，含超时/回收/幂等）+ 脚本库约定。**

## 7. 上下文治理（"越用越不好用"的根治）

**三层上下文生命周期（对标 Hermes strategic-compact，但我们做成本地内核级）：**
1. **上下文预算**：每次会话设 token 预算，超了自动压缩/归档旧消息（内核 context_cleaner 已有）
2. **记忆分层**：热记忆(上下文) / 温记忆(检索) / 冷记忆(归档) —— 超脑内核已做 L0-L4
3. **工具分级**：工具不全部载入，按任务相关性惰性注入（避免工具列表臃肿拖慢+混淆模型）

---

## 8. 分阶段路线

- **Phase 1 稳定性**：熔断器 + 重试预算 + 全局超时 + 命令沙箱回收 + 危险门禁
- **Phase 2 上下文治理**：token 预算自动压缩 + 工具惰性加载 + 记忆分层打通
- **Phase 3 发布**：install.sh/ps1 + 打包 + GitHub Actions 多平台
- **Phase 4 脚本库**：常用运维操作沉淀复用脚本库

> 全部机制都要求**真实验证**（不堆营销词）：熔断器用假服务器测、沙箱回收用真实任务测、安装脚本在干净环境测。
