# Super-Agent 战略规划与架构路线（ROADMAP v3）

> 一句话纲领：**LLM 是发动机已经很强，我们做的是那个不会越用越坏的"载体"。**
> 载体的第一性原理 = **一切资源预算受限，按重要度分级、按活跃度调度、按生命周期淘汰。**

---

## 0. 核心洞察：为什么所有 agent "越用越不好用"

| 症状 | 病根 | 类比 |
|---|---|---|
| 上下文太多、越来越贵、越用越笨 | 上下文只增不减，无预算无压缩无淘汰 | 内存泄漏 |
| 记忆太短/太多/太杂乱 | 记忆无分层无去重无GC | 垃圾堆 |
| skills/MCP/工具混乱臃肿 | 全量载入，无分级无惰性 | CPU 满载 |
| 任务越拖越慢、越卡 | 无分配调度，无预算无超时 | 进程爆炸 |
| **聊天/截图堆积** | 图片无统一存放、无压缩、无保留策略 | 磁盘爆满 |

**结论：agent 缺的不是能力，是像操作系统的"资源调度器"。**

## 2. 架构定位（语言策略，按你的测试结论定稿）

```
superbrain-2.0/  ← 大脑 = Rust 内核（记忆/检索/状态，独立仓库分开更新）
super-agent/     ← 身体 = Python 载体（编排/工具/生态，独立仓库）
客户端层         ← Rust 客户端（你已实测 Rust 性能强 → 用 Rust 做主客户端）
                 （Windows / Linux / macOS 皆为客户端，同一套）
```

**语言分工：**
- **Rust**：客户端 / 内核 —— 稳定 + 高性能
- **Python**：身体编排 / 工具生态 / TUI —— 生态最全
- **原生脚本**：系统级操作（Linux sh / Windows ps1 / macOS zsh）用于安装器

**内部结构（已验证保留）**：kernel 孔位层 / loop 自主执行 / config 配置 / stats 计费 / tui 多表面

## 3. 长期任务 + 死循环自查（特重要模块）

**失败三次不是"停止"，而是"进入自查"。**

### 3.1 自查模块（Self-Check）
1. **诊断**：为什么失败？（权限/环境/缺信息/不可行/参数）
2. **根因自查**：DNS？防火墙？服务没起？地址变了？（诊断工具验证，不猜）
3. **自愈尝试**：可自动修则修（重装服务、换地址、清缓存、重连）
4. **复验**：修复后重验，真成功才进入下一步

### 3.2 连贯任务队列（依赖有序）
任务 1→2→3 有依赖：**任务1 未自查通过 + 未真正成功，绝不进任务2**；每完成一个验证+自查确认；任一环失败 → 该环及后续全部进"未完成清单"。

### 3.3 上报 / 未完成清单 / 进度提示
- **进度条**：长任务显示当前/总步数、每步状态
- **失败上报**：明确提示"哪步失败、为什么、已记录"
- **未完成清单**：失败/暂停任务进清单，可 /resume 续跑
- **通知**：跨表面（TUI/Telegram）推送任务开始/完成/失败

## 4. 安全哲学（防误伤，不妨碍自己人）

- ✅ 不设死板门禁：重启 agent、执行命令不被无理拦截
- ✅ 密码自管：密码本加密存储，**可解密查看明文**（非银行/支付密码）
- ✅ 服务器密码等收录：自己的凭据密码本统一管理，重要性分级
- ⚠️ 仅保留防误伤：`rm -rf /` 等轻提醒，不拦截自己人

## 7. 图片资产：存放 + 压缩（你要的完整方案）

**你的核心要求：对话产生大量图片 → 统一存放 + 保留时长 + 压缩入库 + 可转换。** 本版写为详细可执行方案。

### 7.1 统一存放（跨客户端一致）
- 所有客户端（Win/Linux/macOS）**同一套资产目录**，对话截图/生成图片统一落到：
  `~/.super-agent/assets/images/`
- 按会话/日期/类型分类：`<session>/<yyyy-mm-dd>_<seq>.png`
- **保留时长设置**（config 可配）：默认保留 N 天，超期自动清理（冷归档可选）

### 7.2 压缩入库（搬 Squoosh 那套开源编码器）
- **搬 `google/squoosh` 开源编码器集**（Rust/WASM）：内嵌
  **OxiPNG / MozJPEG / WebP / AVIF / JPEG XL**
- **存储统一用 PNG**（最不易出错，压缩率足够 80-90%）
- 其它编码器传入 → **自动压缩成 PNG 入库**，像 Squoosh 网站一样可转换
- Rust 客户端内嵌这些编码器 → 本地压缩，无需上传

### 7.3 精细策略
| 场景 | 建议格式 | 说明 |
|---|---|---|
| 对话截图 | PNG（入库基准） | 最稳，压缩率 80-90% |
| 照片 | AVIF | 现代最佳质量体积比 |
| 无损/宽色域 | JPEG XL | 最佳但支持有限 |
| 图形/图标 | WebP / OxiPNG | 高效 |

## 8. 上下文治理（精挑输入，不是全塞）

1. **上下文预算**：每次会话设 token 预算，超了自动压缩/归档
2. **记忆分层**：热/温/冷 —— 大脑已做 L0-L4
3. **工具分级**：不全部载入，按任务相关性惰性注入
4. **项目感知精挑输入**：
   - 输入前明确：在做什么项目？当前目标？
   - 只挑当前项目相关的记忆/工具/历史喂给模型，无用废话不输入
   - 长历史按项目/时间切片，只带当前切片

## 9. 分阶段路线

- **Phase 1 稳定性**：自查模块 + 连贯任务队列 + 熔断/重试/超时 + 未完成清单 + 进度条 + 命令沙箱回收
- **Phase 2 上下文治理**：token 预算压缩 + 工具惰性加载 + 项目感知精挑 + 记忆分层打通
- **Phase 3 发布**：Rust 客户端 + install.sh/ps1 + 打包 + GitHub Actions 多平台
- **Phase 4 资产与存储**：存储空间规划 + 资产文件夹 + **图片压缩（搬 Squoosh 编码器，PNG 入库，可转换）**
- **Phase 5 密码本与安全自管**：加密密码本 + 可解密查看 + 防误伤保护

> 全部机制都要求**真实验证**（不堆营销词）：自查用坏服务器测、进度条用长任务测、图片压缩用真实截图测体积、安装脚本在干净环境测。
