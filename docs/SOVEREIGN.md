# 主权开放架构 Sovereign Architecture —— AI 掌控一切，但底层不可撼动

> 用户定调（确认 2026-09）：
> - 两个层面：**层面一 AI 对话/执行/思考**（智能核心开放），**层面二 AI 掌控智能体**（支配+自我修改）。
> - 三层结构解决「开放 vs 稳定」：**稳定内核不可撼动（AI 只读）+ 开放插件层（AI 自由进化）+ 升级治理层（底层演进走文档/排队/门禁）**。
> - AI 自由区想干嘛干嘛；内核只读，AI 改不进去；升级走正规流程 → **掌控一切，但不乱改**。

## 1. 设计哲学（继承 xray 内核观）
核心纯、只出接口；外围开放扩展。AI 是主人，智能体是身体/四肢；身体的核心不可被 AI 撼动，
但身体的外围（插件/能力）完全开放给 AI 自由扩展、思考、进化。

## 2. 两个层面
| 层面 | 内容 | 开放动作 |
|---|---|---|
| 层面一 | AI 对话·执行·思考（智能核心） | 完整上下文/全量工具/批量执行/多模态/自我反思规划；不被 curator/门禁削弱 |
| 层面二 | AI 掌控智能体（支配+自我修改） | AI 支配全部能力(执行/autopilot/记忆/工具)；能增插件/改技能/扩展能力，但仅限插件层 |

## 3. 三层结构
```
① 稳定内核（不可撼动 · AI 只读）
   执行daemon / sandbox / 权限模型 / 记忆内核 / BrainPort契约 / 安全底座
② 开放插件层（AI 自由区 · 随用随装即装即卸）
   tool插件 / skill / autopilot后端 / GUI自动化 / 小功能
③ 升级治理层（底层演进正规通道）
   需求/建议/升级/优化/修复/开发 → 文档存档(含代码文档) → 排队 → 门禁 → 测试 → 并入
```

## 4. 开放与保护边界
| 对象 | AI 权限 |
|---|---|
| 插件层 | 读+写+建+卸（自由） |
| 稳定内核 | **只读**（看得见动不了） |
| 底层升级 | 只能提交「需求文档」进治理队列，不直接改 |

## 5. 防乱改机制
- 内核只读：AI 写操作被内核边界拦截（写仅落插件层）
- 插件隔离沙盒：改坏一个插件不波及内核
- 升级门禁：需求文档存档 → 排队 → 门禁审查 → 测试通过 → 才并入内核
- 全量留痕（git+账本）+ 可回滚（restore_last_good）

## 6. 关键组件
- `sovereign/self_mod.py`：自我修改，**限定插件层**（add_tool/edit_skill/add_backend/change_plugin_config）
- `sovereign/upgrade_queue.py`：升级治理——需求文档(含代码文档)存档 → 队列 → 状态机(待审查/待开发/待测试/待并入/已并入/驳回)
- `plugins/registry.py`：开放式插件注册中心（随用随装即装即卸，隔离沙盒）
- 内核只读门：所有写操作按目标分区——插件区放行，内核区拒绝并提示走升级队列

## 7. 自进化思考 Self-Evolution Thinking（贯穿核心引擎）

**AI 只做：观察、思考、准备提案。执行优化必须用户批准。**

```
循环：观察 → 思考 → 提案 → 批准 → 执行 → 复盘 → 下一轮
```

- **观察**(日常自动记录)：错误(执行daemon结构化错误) / 痛点(重复劳动/低效/受限) / 优化点(流程/工具/配置) / 迭代建议(架构/能力升级)
- **思考+记忆+准备**：AI 把每点想清楚成「进化提案」(改哪里/怎么改含代码文档/预期收益/风险/优先级)，存进化提案库
- **批准(用户掌舵)**：提案交用户批准；AI 不能自行执行底层优化；批准→落地，驳回→归档/调整
- **执行+复盘**：落地后记效果，进入下一轮 → 架构持续变好

**关键边界**：底层/架构优化【必须批准】才执行；插件层自由区仍可 AI 自由。

## 8. 关键组件
- `sovereign/self_mod.py`：自我修改，**限定插件层**（add_tool/edit_skill/add_backend/change_plugin_config）
- `sovereign/upgrade_queue.py`：升级治理——需求文档(含代码文档)存档 → 队列 → 状态机(待审查/待开发/待测试/待并入/已并入/驳回)
- `plugins/registry.py`：开放式插件注册中心（随用随装即装即卸，隔离沙盒）
- 内核只读门：所有写操作按目标分区——插件区放行，内核区拒绝并提示走升级队列
- `evolution/observer.py` 观察记录 / `evolution/proposer.py` 思考准备提案 / `evolution/ledger.py` 进化提案库状态机 / `evolution/approval.py` 用户批准闸门

## 9. 分阶段
| 阶段 | 交付 |
|---|---|
| ① 插件层骨架 | plugins/registry（装/卸/隔离/即用）+ 内核只读门 ✅ |
| ② 自我修改(限定插件) | sovereign/self_mod：增插件/改技能/扩展能力，全留痕可回滚 ✅ |
| ③ 自进化思考 | evolution/：observer观察记录 → proposer思考提案 → ledger库 → approval批准闸门（批准才执行） ✅ |
| ④ 升级治理 | sovereign/upgrade_queue：需求文档存档→排队→门禁→测试→并入 |
| ⑤ 层面一开放 | 完整上下文/全量工具/思考进化循环接到 AI 自主 |
| ⑥ 信任模式 | guided vs sovereign 切换 |

## 10. 验证纪律
- 内核只读：AI 尝试写内核 → 断言被拒并提示走升级队列（不是静默失败）
- 插件即装即卸：装一个坏插件 → 隔离不波及内核，卸载即净
- 自进化：日常错误/痛点被 observer 记录 → proposer 形成提案 → 未经批准不执行（硬断言）→ 批准后落地
- 升级治理：提交需求文档 → 进队列 → 门禁 → 测试 → 并入 → 全程留痕
- 回滚：AI 改坏插件/配置 → restore_last_good 还原
- 全程真实跑通，不用 mock 冒充
